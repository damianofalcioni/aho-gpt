# Aho! GPT specification

## Product

The visible app name is `Aho! GPT`, inspired by the Italian “Aho!” exclamation. The repository and assumed GitHub Pages path are `aho-gpt`. The base application ID and Java namespace are `aho.gpt`; retain the `.wear` device suffix and `.debug` build suffix. The `fdroid` distribution adds `.foss` before the device suffix. Keep Android adapters under `aho.gpt.android` and protocol/session code independently JVM-testable.

Use the approved native Android XML vector trace of the supplied Aho!/GPT calling-person artwork, without bundling the PNG or adding runtime tracing libraries. The tappable home-screen logo has white artwork on the same dark surface as its button; enclosed details follow the button's normal and focused surface colors. Keep native path compatibility with Android 6. Launcher artwork and the TV banner retain their black-on-white treatment. Provide a legacy launcher icon for Android 6–7 and an adaptive icon with a white background and safely inset artwork on Android 8 and later. Give the home logo greater prominence alongside a compact circular, icon-only microphone button distinct from the app logo, retaining its spoken accessibility label.

Provide a lightweight Android, Android TV and Wear OS AI harness. Use Java, native Android APIs, no runtime dependencies, and the reference project's focused architecture and zero-violation complexity checks. Use vibe-navigator's black background, white iconography, rounded dark surfaces and outlined controls throughout the native UI. Match its inherited native Material accent for active switches and native link-text colors for About links. The main screen contains a tappable app logo, the account and model names directly on the background, and a microphone button. The central text has no labels, tool count, instructions or enclosing box; short status placeholders cover missing setup. Logo and name rows open About & settings; microphone invocation redirects there when account or model setup is missing. Keep account, model, speech, tools, logging and diagnostic controls on About & settings. Put app information first, matching the reference's title, version, description, icon links, copyright and brief Android/OpenAI credits. Follow with divided settings sections and diagnostics. Do not show a bottom usage-help section. Match the reference's regular-weight headings, 16dp phone page inset, 44dp gear controls, 40dp information controls, compact row spacing, muted secondary text and colored source/issue icons. Under AI Providers show ChatGPT and Custom rows with a gear, saved enable switch and info button, matching TTS. Do not show the account/model/app-action summary or separate account action buttons. Under Device show only Tools; access and assistant settings are reached through Diagnostic. Show TTS provider status below its row only while checking or when unavailable. Keep STT provider status in its information dialog; do not show helper text below the STT row. Use GitHub/GitHub Pages links under damianofalcioni/aho-gpt. Homepage, changelog, privacy policy and terms of service open the corresponding site pages. Keep contextual information and README concise and written for end users, explaining actions and essential privacy implications without implementation details. Keep technical contracts in this specification. Do not add an in-page back button; use Android system navigation. Requests, tool execution and answers use a transient voice panel and overlay; no chat screen. Provide visible D-pad focus and layouts sized for phone, TV and watch screens, including a side-by-side TV names/microphone arrangement.

## Diagnostic

After settings, show a Diagnostic section with a 22sp regular heading and only five compact 44dp access rows: microphone permission, overlay permission, screen access, default assistant and log folder access. Use a 12dp colored dot, 15sp label and 14sp status. Rows are touch/D-pad accessible and expose the label and status together. Show only OK or KO: green OK means granted or writable, red KO means missing access or selection, and yellow KO means the folder check is pending. Do not show hardware, mute, provider, network, account, model or settings-switch entries.

Tapping a row opens Android UI directly, without an app details dialog. Microphone opens this app's Android settings; screen access opens accessibility settings; overlay and default assistant open their system settings. Public Android intents do not guarantee a particular permission subpage or picker on every device. Microphone status checks only RECORD_AUDIO, screen access checks the exact enabled service component in Android settings while accessibility is globally enabled, independently of whether the service is currently connected, and overlay status checks its independent grant. On Android 6–9, log access opens app settings for phone storage or the system folder-grant picker for the selected SD card. Accept only that card's valid folder grant, without enabling logging or switching storage. On Android 10+, MediaStore needs no user storage grant, so this row opens the selected log folder in the system file picker. Internet and package visibility do not need runtime grants; do not add rows for them.

Refresh local status only while settings is foreground and cancel UI callbacks on pause/destruction. Check log access off the UI thread on page resume, storage-selection changes and permission results using a temporary write to the selected destination, then remove the test file. Do not redirect output, request permissions, enable logging, contact OpenAI, acquire microphone audio, play speech or retain screen content during diagnostic checks.

## Voice and continuity

The transient voice panel uses a separate task and a compact bottom card (156dp high on phone/TV, capped at 640dp wide, with round-screen padding on watches). Put scrollable, left-aligned status and answer text to the left of a 48dp circular microphone and a matching outlined circular × close control below it. Keep both controls accessible by touch, D-pad and spoken labels. Fade text at the vertical scrolling edges when more content is available. Use a translucent rounded background with a slow opacity pulse only while listening or actually playing speech; keep text and controls steady and stop animation when hidden or detached. Finishing it with × (announced as Close), Android Back or automatic dismissal removes that task from Recents, whether opened by the microphone button, the system assistant shortcut or an external TV mapper. Preserve the normal app and caller tasks. Automatically dismiss the panel three seconds after recognition ends without a result (including empty results), session expiry, or an error (including microphone permission denial or playback failure). Keep the answer or error visible during this delay. A new microphone invocation cancels pending dismissal; closing or destroying the panel cancels the timer. Dismissal must survive foreground changes without interrupting active inference or speech playback.

Expose separate Thinking and Executing tool states in the JVM voice lifecycle. Forward tool progress to the panel before execution and return to Thinking before the next model request. When another app takes foreground, mirror the current panel and close control in a non-focusable accessibility or permitted application overlay. Keep it visible through inference, tools and playback, without an overlay expiry timer. Closing either panel cancels pending work. Remove the overlay when the activity resumes or is closed; ignore late progress from retired requests. Without accessibility or overlay permission, Android cannot show the panel over other apps; the activity still retains its state. Do not dismiss active inference or tool execution when the target app takes foreground.

Use platform STT and TTS unless Custom speech APIs, Realtime or GPT-Live are enabled. Prefer on-device STT if available; clearly report missing providers. User invocation starts a microphone session once the panel is foreground and microphone permission has been granted. Answer completion transitions directly into listening without another microphone press. After successful answer playback, or immediately after displaying an answer with TTS off, automatically listen for up to eight seconds while the voice panel is foreground. A follow-up beginning in that interval retains context; otherwise start a fresh conversation. Silence or recognition timeout ends listening, shows Finished and applies the three-second dismissal delay; do not restart recognition in a silence loop. Other errors show their error state and apply the same delay without automatic retries. Keep the answer visible during follow-up listening and the dismissal delay without countdown instructions or session-ended help text. Stop recognition on backgrounding and schedule dismissal. If the panel returns before dismissal, interrupted listening automatically resumes. Answer completion in the background also schedules dismissal without opening the microphone; returning before dismissal resumes listening automatically. Do not restart finished or failed sessions on resume. Keep history in memory, bound its size, and clear it after expiry, failure or lifecycle destruction. No wake-word or persistent background listener.

Instruct the model to answer in the language of the latest spoken request and match its tone and formality on each turn, including changes during follow-ups. Formal requests receive formal replies; casual requests and modern slang receive a natural matching style without forced slang or exaggerated imitation. Explicit requests for a different answer language or style take precedence. Keep answers clear, accurate and concise. Give the direct answer in short, simple sentences, avoiding long sentences, repetition and unnecessary introductions. Add detail only when requested or needed for clarity or accuracy. This is model guidance, not a deterministic language or style guarantee.

Provide a Languages section starting with Use System Language, followed by Text to Speech (TTS) and Speech to Text (STT), each containing a label, gear, enable switch and info button in one line. The app-language switch defaults on and uses the first supported device language, falling back to English. Its gear stays available in either switch state and opens a themed Language spinner with English and Italiano, a short explanation and OK/Cancel. Initially select the supported system language. OK saves the manual choice; Cancel discards edits. Saving while automatic selection is on leaves the effective language unchanged. Turning automatic selection off uses the remembered manual choice, capturing the current supported system language if none is saved. Reenabling it keeps the manual choice. Apply display-language changes to native screens, including screens returning from settings, without changing system locale, speech preferences or model answer-language guidance. Provide English and Italian string resources and keep both languages in app bundles.

Save the platform speech enable preferences independently. With Custom speech APIs, Realtime or GPT-Live selected, keep both platform speech switches off and visually muted without changing their saved choices; accept touch, D-pad and accessibility activation only to show a short server-speech explanation toast; server capture and playback ignore these switches and need no installed Android speech providers. Keep the gears available for local setup and explicit Android tests. Returning to platform speech restores the saved choices, subject to provider availability. In platform mode, keep TTS off and visually muted until its provider is available. A refused TTS enable attempt shows a short checking or unavailable toast and preserves the saved choice. Keep unavailable STT off and visually muted, but tappable by touch, D-pad and accessibility so an enable attempt can give feedback. Refuse enabling STT without a usable provider, preserve its saved preference and recheck availability on each enable attempt. For platform STT, require an enabled, exported recognition service in an enabled app with its own microphone permission, as in Vibro. An available on-device recognizer is preferred; otherwise create recognition against the first usable service from that filtered inventory so a stale system default cannot select an unusable declaration. An activity-only recognizer cannot serve this app's embedded SpeechRecognizer. Provider inventory does not verify speech operation or language support; keep explicit speech tests in the gears. An absent or disabled Google app does not block another usable STT provider or TTS engine. Show a short text toast only when the user tries to switch STT on, no usable provider is available and the Google app is installed but disabled. Do not show a dialog, open Android settings or notify when opening or resuming settings. Cancel speech-switch toasts on refresh, pause or destruction. Keep gears usable for provider setup. In platform mode, STT off prevents microphone acquisition; TTS off keeps answers visible and still permits automatic follow-up listening when STT is enabled. Preserve saved enable choices when a provider temporarily disappears.

Each speech gear opens a native configuration dialog following Vibro’s speech dialogs: 20dp horizontal padding, 8dp top and 4dp bottom padding, a 16sp label beside a rounded 48dp-minimum spinner, and a right-aligned 52dp Android speech-settings button above OK. TTS has a Voice spinner and a 44dp play control; STT has only the Language label and spinner in its selection row. Put the explicit recognition Test action in the STT configuration dialog footer beside OK. The STT information dialog contains only details and Close. Ready status is hidden; checking, unavailable, unverified and preview results remain visible. Android speech settings retain a general-settings fallback. Independently save STT and TTS language choices, each defaulting to the device language. TTS lists installed voices reported by the default engine, saves the selected voice and its locale, and uses them during answers. Its device-language option clears the explicit voice and locale; retain existing saved language-only choices visibly. Missing selected voices fail visibly. Explicit TTS previews may play while automatic playback is off. STT previews require microphone permission and display local results without inference, tools or conversation history; stop previews on backgrounding or dismissal. Pass the chosen BCP 47 locale to recognition and playback. Show the requested recognition language by name and tag throughout platform recognition and speech API transcription acquisition, including follow-ups. Realtime and GPT-Live ignore that language choice and show only Listening, including follow-ups. Query ready STT languages from the same recognizer used for listening on Android 13 and later; query installed TTS voices and their languages from the default playback engine. Capability queries must not open the microphone or download models. If a recognition provider cannot report support, clearly label device-locale choices as unverified. Do not advertise downloadable STT languages or uninstalled TTS voices as ready. Report missing or unsupported language data, preserve a visible answer on playback failure, and do not open follow-up listening after failed playback. TTS language changes the playback voice, not answer translation.

### GPT-Live

Below Use Realtime API, show Use GPT-Live API with the same label, 44dp gear, switch and 40dp information control. Default it off. Speech APIs, Realtime and GPT-Live are mutually exclusive; all off uses Android speech. Save all mode flags and speech choices atomically with the parent OK. Cancel discards drafts. Restored conflicts prefer GPT-Live, then Realtime. Disable all mode switches during support checks and block saving until the check ends. Endpoint/token changes cancel checks and clear all draft modes. Main-model changes invalidate Realtime and GPT-Live checks. Changing a mode's own model or voice invalidates only that mode. Cancel work and ignore retired results on pause, dismissal and provider revision changes.

The GPT-Live gear opens its own native scrollable dialog with Voice model and Voice spinners, Refresh and OK/Cancel. Default to `gpt-live-1` and `marin`; keep the main Custom model as the independent Responses reasoning/tool model, including explicitly selected `gpt-6-luna`. Discover model IDs from the configured server without guessing capabilities from names. Retain saved values and allow Custom identifiers. For the exact OpenAI base, offer the documented GPT-Live voice names; other providers may supply their optional voice inventory. Clearly label inventories, published suggestions and unavailable lists. Keep English and Italian resources, native focus and settings available while the mode is off. Nested OK updates only the parent draft and preserves other modes' choices.

Use the documented [GPT-Live primary WebSocket](https://developers.openai.com/api/reference/resources/live/primary-websocket) at `<base>/live/sessions`, with no model query. Reuse the existing masked WebSocket transport, host-bound optional custom token, TLS checks, redirect refusal and cancellation. Send `session.start` with the chosen voice model, `store=false`, mono PCM16 at 24 kHz, selected voice, bounded text history and Responses delegation configured with the main model, current instructions and enabled functions. Require `session.started` with the requested models, voice, delegation and audio format. A support check starts and gracefully closes this session without audio, inference, playback or tools; session time may be billed. A provider invalid-request rejection shows a fixed setup message explaining that the main Model must be a reasoning model and that voice settings must be checked. Other failures retain the availability message. Never display or log raw provider error text. It confirms configuration only, not backend or voice operation. First available resolves the main model once per turn from the same server; never replace an explicit selection.

Preserve the existing foreground microphone capture and silence limits, microphone permission checks and eight-second follow-up window. Preserve platform STT/TTS preferences without applying them to GPT-Live sessions. Installed Android speech services are unnecessary. Capture a complete turn, convert it to raw 24 kHz PCM and send `session.input_audio.append`; a cancellable worker supplies silence afterward to advance the Live timeline without further microphone acquisition. This implementation buffers speech and does not support simultaneous listening/playback or spoken interruption. Play buffered replies independently of the platform TTS switch; Live voice charges may apply. Keep local Android speech tests local. Close and discard each turn's session, including when the panel is closed or the provider changes. Do not store audio, remote session IDs, transcripts or conversations.

Track nested `response.event` streams by delegation and response IDs. Rebuild output from complete indexed `response.output_item.done` events, check announced item IDs and reject missing, duplicate, foreign or malformed items. Only `response.completed` with completed status may return a fully validated batch to the shared agent loop. Partial arguments, failed/incomplete responses and transport errors never execute tools. Reuse argument validation, permission/enable checks, tool revisions, request scopes and per-turn receipt caching. Send new receipts using `response.item.create`, then `response.create`; do not resubmit historical receipts to a new Live session. No automatic model or speech-mode fallback.

Use the completed backend answer for visible text and temporary history when work is delegated. GPT-Live may answer conversational requests directly despite delegation guidance. If no delegation or nested backend event has occurred, a bounded spoken transcript plus settled speech audio may return an assistant message without waiting for a backend response. Never synthesize tool calls from speech or use an acknowledgment to complete delegated, incomplete or failed backend work. Preserve the already-settled audio gate for direct replies. Replace the latest audio request with its input transcript for follow-up startup history; do not replay previous tool receipts or captured audio. Startup history is text-only and capped at 20,000 characters, otherwise omitted. Bound transcripts at 80,000 characters and each reconstructed backend output at 2 million characters. Retain speech audio up to 24 MB and discard extended idle silence. GPT-Live has no output-audio-done event: after backend completion, use a two-second PCM silence gate before buffered playback, then request `session.close` and require `session.closed` with `close_requested`. This silence gate is a playback heuristic, never proof of task completion; pauses and voice timing need live integration testing. Discard intermediate tool-round speech. Use 15-second startup/close socket timeouts and 60-second response inactivity checks; continuously arriving silence must not keep a stalled response alive indefinitely. Failure remains visible and never claims successful delivery of speech.

JVM fixtures cover startup validation, independent models, complete backend/tool exchanges, malformed and incomplete calls, cancellation, bounded audio, text-only output, saved mode precedence and the Live endpoint path. The optional server-speech instrumentation fixture also covers separate GPT-Live spinners and nested OK/Cancel. Static/build checks do not establish live GPT-Live access, provider behavior, voice timing or physical-device playback.

Tool configuration revisions retire model responses made with older choices. Before a new request with changed choices, retain only the latest spoken request and discard prior temporary context so previously discovered disabled metadata is not sent again. A revision check immediately before transport and after a response prevents further rounds from using old settings; dispatch checks remain authoritative for queued work.

Scan all visible installed applications for accessible exported manifest intent filters and expose a searchable local catalog to the model. Support explicit activities, services and broadcasts, subject to Android permissions and execution restrictions. Do not claim extras' semantics or inaccessible capabilities can be inferred. Catalog metadata remains local until a search tool returns selected entries. Rescan explicitly and at process start.

Prioritize discovered app launchers in catalog search results and identify them explicitly. Opening an app by intent uses its discovered exported activity, MAIN action, phone or TV launcher category and launcher task flags. When a suitable launcher is found, invoke it directly without first hiding the voice activity or navigating Home. Return dispatch failures without claiming verified completion; Android background-launch restrictions still apply.

Supplement manifest parsing with public package-resolver queries for phone/TV launchers and general HTTP/HTTPS handlers, including split APK activities. Do not claim complete discovery of other split-manifest filters. Expose two device-tool functions, or four when accessibility is available, with at most 25 selected catalog entries per search page; keep the full inventory local.

Extend the discovery function with an on-demand overview of available standard-action categories, declaration counts and distinct-app counts, without app identities or individual capability IDs. Support structured AND filters for app name, exact package, category, component kind, action, URI scheme and MIME type, including wildcard MIME matching. Rank exact app matches ahead of substring matches and prefer launchers within equal relevance; preserve keyword search and pagination. Instruct the model to use the overview for unfamiliar abilities and targeted filters for known goals, and to narrow or paginate before claiming a capability is absent.

Describe each result with its standard category, meaning, usage limits and whether its semantics are known. Derive descriptions only from documented standard Android activity contracts; keep custom and non-activity intent semantics unknown. Describe declarations rather than guaranteed outcomes. Explicitly report unsupported image-stream extras, URI grants and returned camera/document data. Discovery must not change execution permissions, argument validation or cancellation behavior.

When the app's accessibility service is enabled, include screen-reading and requested UI action tools. Exclude password nodes; treat other screen text and app metadata as untrusted input. No passive event retention or key interception. Mutating tools carry out the active spoken request and return actual dispatch results; unclear targets must be clarified by voice.

Validate tool arguments locally against their advertised schema, including exact names, types, enums, required fields and size limits. Reject duplicate JSON keys, trailing data and unsupported syntax before execution. Give each recognized spoken turn its own cancellable execution scope, independent of conversation continuity. Do not impose a total turn deadline, tool-round cap or call-count cap; transport and queued-dispatch timeouts still apply. Check authority after model responses and immediately before tools, including on the execution thread for queued Android work. Closing the panel revokes the scope; already dispatched external actions cannot be undone. Ignore callbacks from retired requests.

Return every tool receipt to the model as a function_call_output linked by call_id, then request the next model response. Continue until the model answers, cancellation or failure. Cache receipts per turn: identical encoded calls with the same ID return the existing receipt, and changed calls reusing an ID are refused. New IDs are not semantically deduplicated; instruct the model not to bypass replay protection or repeat uncertain mutations. Report mutation outcomes as refused, rejected, accepted or unknown with explicit dispatch evidence and no claim of verified task completion. Unexpected execution exceptions use fixed codes. After UI actions invalidate cached screen nodes. These controls enforce local execution contracts, not independent semantic verification of the spoken request.

For a task inside a named app, instruct the model to try a suitable discovered action intent first. If none is usable or dispatch is rejected, separately search category open_app for that app without action, scheme, MIME or task-keyword filters and invoke its discovered launcher. After accepted dispatch, check the visible target with a fresh screen read and use enabled accessibility tools for remaining requested steps. Use Home, launcher icons or Recents to open the app only when its launcher intent is unavailable or rejected. Never bypass disabled-tool refusals or retry unknown mutation outcomes. Keep fallback within the same clear spoken request. Require fresh screen reads after navigation and node IDs from the latest read. Respect platform permissions and inaccessible controls; clarify ambiguous targets and report unavailable or failed fallback without claiming success. This policy is model guidance rather than a deterministic execution guarantee.

Treat PWAs packaged as visible Android applications like other discovered applications. Plain home-screen website shortcuts are outside the installed-app catalog; do not enumerate launcher-private shortcut data or infer that an absent native app makes its shortcut unclickable. When accessibility is enabled, use Home, a fresh screen read and the matching visible shortcut node for the requested launch.
