# Aho! GPT specification

## Product

The visible app name is `Aho! GPT`, inspired by the Italian “Aho!” exclamation. The repository and assumed GitHub Pages path are `aho-gpt`. The base application ID and Java namespace are `aho.gpt`; retain the `.wear` flavor and `.debug` build suffixes. Keep Android adapters under `aho.gpt.android` and protocol/session code independently JVM-testable.

Use the approved native Android XML vector trace of the supplied Aho!/GPT calling-person artwork, without bundling the PNG or adding runtime tracing libraries. The tappable home-screen logo has white artwork on the same dark surface as its button; enclosed details follow the button's normal and focused surface colors. Keep native path compatibility with Android 6. Launcher artwork and the TV banner retain their black-on-white treatment. Provide a legacy launcher icon for Android 6–7 and an adaptive icon with a white background and safely inset artwork on Android 8 and later. Give the home logo greater prominence alongside a compact circular, icon-only microphone button distinct from the app logo, retaining its spoken accessibility label.

Provide a lightweight Android, Android TV and Wear OS AI harness. Use Java, native Android APIs, no runtime dependencies, and the reference project's focused architecture and zero-violation complexity checks. Use vibe-navigator's black background, white iconography, rounded dark surfaces and outlined controls throughout the native UI. Match its inherited native Material accent for active switches and native link-text colors for About links. The main screen contains a tappable app logo, the account and model names directly on the background, and a microphone button. The central text has no labels, tool count, instructions or enclosing box; short status placeholders cover missing setup. Logo and name rows open About & settings; microphone invocation redirects there when account or model setup is missing. Keep usage, permission, assistant, tool-rescan and sign-out controls on About & settings. Put app information first, matching the reference's title, version, description, icon links, copyright and brief Android/OpenAI credits. Follow with divided settings sections and help. Match the reference's regular-weight headings, 16dp phone page inset, 44dp gear controls, 40dp information controls, compact row spacing, muted secondary text and colored source/issue icons. Pair account and device action buttons with contextual information buttons. Show speech-provider status below its row only while checking or when unavailable; keep ready status in its information dialog. Use assumed GitHub/GitHub Pages links under damianofalcioni/aho-gpt; show privacy and usage details locally. Keep help, instructions and README concise and written for end users, explaining actions and essential privacy implications without implementation details. Keep technical contracts in this specification. Do not add an in-page back button; use Android system navigation. Requests, tool execution and answers use a transient voice panel and overlay; no chat screen. Provide visible D-pad focus and layouts sized for phone, TV and watch screens, including a side-by-side TV names/microphone arrangement.

## Voice and continuity

The transient voice panel uses a separate task and a compact bottom card (156dp high on phone/TV, capped at 640dp wide, with round-screen padding on watches). Put scrollable, left-aligned status and answer text to the left of a 48dp circular microphone and a matching outlined circular × close control below it. Keep both controls accessible by touch, D-pad and spoken labels. Fade text at the vertical scrolling edges when more content is available. Use a translucent rounded background with a slow opacity pulse only while listening or actually playing speech; keep text and controls steady and stop animation when hidden or detached. Finishing it with × (announced as Close), Android Back or automatic dismissal removes that task from Recents, whether opened by the microphone button, the system assistant shortcut or an external TV mapper. Preserve the normal app and caller tasks. Automatically dismiss the panel three seconds after recognition ends without a result (including empty results), session expiry, or an error (including microphone permission denial or playback failure). Keep the answer or error visible during this delay. A new microphone invocation cancels pending dismissal; closing or destroying the panel cancels the timer. Dismissal must survive foreground changes without interrupting active inference or speech playback.

Expose separate Thinking and Executing tool states in the JVM voice lifecycle. Forward tool progress to the panel before execution and return to Thinking before the next model request. When another app takes foreground, mirror the current panel and close control in a non-focusable accessibility or permitted application overlay. Keep it visible through inference, tools and playback, without an overlay expiry timer. Closing either panel cancels pending work. Remove the overlay when the activity resumes or is closed; ignore late progress from retired requests. Without accessibility or overlay permission, Android cannot show the panel over other apps; the activity still retains its state. Do not dismiss active inference or tool execution when the target app takes foreground.

Use platform STT and TTS. Prefer on-device STT if available; clearly report missing providers. User invocation starts a microphone session once the panel is foreground and microphone permission has been granted. Answer completion transitions directly into listening without another microphone press. After successful answer playback, or immediately after displaying an answer with TTS off, automatically listen for up to eight seconds while the voice panel is foreground. A follow-up beginning in that interval retains context; otherwise start a fresh conversation. Silence or recognition timeout ends listening, shows Finished and applies the three-second dismissal delay; do not restart recognition in a silence loop. Other errors show their error state and apply the same delay without automatic retries. Keep the answer visible during follow-up listening and the dismissal delay without countdown instructions or session-ended help text. Stop recognition on backgrounding and schedule dismissal. If the panel returns before dismissal, interrupted listening automatically resumes. Answer completion in the background also schedules dismissal without opening the microphone; returning before dismissal resumes listening automatically. Do not restart finished or failed sessions on resume. Keep history in memory, bound its size, and clear it after expiry, failure or lifecycle destruction. No wake-word or persistent background listener.

Instruct the model to answer in the language of the latest spoken request and match its tone and formality on each turn, including changes during follow-ups. Formal requests receive formal replies; casual requests and modern slang receive a natural matching style without forced slang or exaggerated imitation. Explicit requests for a different answer language or style take precedence. Keep answers clear, accurate and concise. Give the direct answer in short, simple sentences, avoiding long sentences, repetition and unnecessary introductions. Add detail only when requested or needed for clarity or accuracy. This is model guidance, not a deterministic language or style guarantee.

Provide a Languages section with separate TTS and STT rows, each containing a label, gear, enable switch and info button in one line. Save the enable preferences independently; disable the switches when their provider is unavailable or an installed Google app is disabled. An absent Google app does not prevent other installed speech providers. Keep gears usable for provider setup. STT off prevents microphone acquisition; TTS off keeps answers visible and still permits automatic follow-up listening when STT is enabled. Preserve saved enable choices when a provider temporarily disappears.

Each gear opens a native configuration dialog with selection, an explicit Test action and an Android speech-settings shortcut with a general-settings fallback. Independently save STT and TTS language choices, each defaulting to the device language. TTS also offers installed voices reported by the default engine, saves the selected voice name and uses that voice during answers; selecting a language resets an explicit voice selection. Missing selected voices fail visibly. Explicit TTS previews may play while automatic playback is off. STT previews require microphone permission and display local results without inference, tools or conversation history; stop previews on backgrounding or dismissal. Pass the chosen BCP 47 locale to recognition and playback. Show the requested recognition language by name and tag throughout acquisition, including follow-ups. Query ready STT languages from the same recognizer used for listening on Android 13 and later; query installed TTS voices and their languages from the default playback engine. Capability queries must not open the microphone or download models. If a recognition provider cannot report support, clearly label device-locale choices as unverified. Do not advertise downloadable STT languages or uninstalled TTS voices as ready. Report missing or unsupported language data, preserve a visible answer on playback failure, and do not open follow-up listening after failed playback. TTS language changes the playback voice, not answer translation.

## OpenAI

Use only OpenAI models discovered from the authorized account. Authenticate using the documented Sign in with ChatGPT public-client flow, PKCE, state, nonce, signature validation, protected token storage and serialized rotating refresh. Request plan usage explicitly, enforce granted scope, and keep API keys out of the app. Provide the requested integrated WebView where supported, with a same-device system-browser fallback. Wear OS has no WebView; current sign-in requires a browser on the watch. Use public Responses with non-persistent streaming requests and explicit history. Only completed responses may trigger tools.

## Device capabilities

Provide a Tools row under Device & permissions with a configuration gear, master enable switch and information button. The native configuration UI lists all recognized device functions and discovered app-action declarations, including disabled entries, with names, individual enable switches and three-dot details controls. Support local search and recycled rows for large catalogs. Details show function descriptions and parameter schemas, or app-action descriptions, usage limitations, components, intent actions, categories, schemes, MIME types, URI authorities and paths, semantics status and current capability IDs. Screen functions remain inspectable before accessibility is granted and state that requirement. Preserve master and individual preferences across restarts and rescans; identify app choices by a stable digest of their component/action/filter contract rather than scan IDs or app labels. The master switch preserves individual choices. Exclude disabled functions from outgoing model tool definitions and associated guidance, and disabled declarations from discovery search, overview and counts. Refuse disabled calls even when the model retains a previously discovered ID; recheck immediately before queued Android dispatch and screen access. These controls do not revoke Android permissions, undo dispatched actions or make an enabled alternative route unavailable.

Tool configuration revisions retire model responses made with older choices. Before a new request with changed choices, retain only the latest spoken request and discard prior temporary context so previously discovered disabled metadata is not sent again. A revision check immediately before transport and after a response prevents further rounds from using old settings; dispatch checks remain authoritative for queued work.

Scan all visible installed applications for accessible exported manifest intent filters and expose a searchable local catalog to the model. Support explicit activities, services and broadcasts, subject to Android permissions and execution restrictions. Do not claim extras' semantics or inaccessible capabilities can be inferred. Catalog metadata remains local until a search tool returns selected entries. Rescan explicitly and at process start.

Prioritize discovered app launchers in catalog search results and identify them explicitly. Opening an app by intent uses its discovered exported activity, MAIN action, phone or TV launcher category and launcher task flags. When a suitable launcher is found, invoke it directly without first hiding the voice activity or navigating Home. Return dispatch failures without claiming verified completion; Android background-launch restrictions still apply.

Supplement manifest parsing with public package-resolver queries for phone/TV launchers and general HTTP/HTTPS handlers, including split APK activities. Do not claim complete discovery of other split-manifest filters. Expose two device-tool functions, or four when accessibility is available, with at most 25 selected catalog entries per search page; keep the full inventory local.

Extend the discovery function with an on-demand overview of available standard-action categories, declaration counts and distinct-app counts, without app identities or individual capability IDs. Support structured AND filters for app name, exact package, category, component kind, action, URI scheme and MIME type, including wildcard MIME matching. Rank exact app matches ahead of substring matches and prefer launchers within equal relevance; preserve keyword search and pagination. Instruct the model to use the overview for unfamiliar abilities and targeted filters for known goals, and to narrow or paginate before claiming a capability is absent.

Describe each result with its standard category, meaning, usage limits and whether its semantics are known. Derive descriptions only from documented standard Android activity contracts; keep custom and non-activity intent semantics unknown. Describe declarations rather than guaranteed outcomes. Explicitly report unsupported image-stream extras, URI grants and returned camera/document data. Discovery must not change execution permissions, argument validation or cancellation behavior.

When the app's accessibility service is enabled, include screen-reading and requested UI action tools. Exclude password nodes; treat other screen text and app metadata as untrusted input. No passive event retention or key interception. Mutating tools carry out the active spoken request and return actual dispatch results; unclear targets must be clarified by voice.

Validate tool arguments locally against their advertised schema, including exact names, types, enums, required fields and size limits. Reject duplicate JSON keys, trailing data and unsupported syntax before execution. Give each recognized spoken turn its own cancellable execution scope, independent of conversation continuity. Do not impose a total turn deadline, tool-round cap or call-count cap; transport and queued-dispatch timeouts still apply. Check authority after model responses and immediately before tools, including on the execution thread for queued Android work. Closing the panel revokes the scope; already dispatched external actions cannot be undone. Ignore callbacks from retired requests.

Return every tool receipt to the model as a function_call_output linked by call_id, then request the next model response. Continue until the model answers, cancellation or failure. Cache receipts per turn: identical encoded calls with the same ID return the existing receipt, and changed calls reusing an ID are refused. New IDs are not semantically deduplicated; instruct the model not to bypass replay protection or repeat uncertain mutations. Report mutation outcomes as refused, rejected, accepted or unknown with explicit dispatch evidence and no claim of verified task completion. Unexpected execution exceptions use fixed codes. After UI actions invalidate cached screen nodes. These controls enforce local execution contracts, not independent semantic verification of the spoken request.

For a task inside a named app, instruct the model to try a suitable discovered action intent first. If none is usable or dispatch is rejected, separately search category open_app for that app without action, scheme, MIME or task-keyword filters and invoke its discovered launcher. After accepted dispatch, check the visible target with a fresh screen read and use enabled accessibility tools for remaining requested steps. Use Home, launcher icons or Recents to open the app only when its launcher intent is unavailable or rejected. Never bypass disabled-tool refusals or retry unknown mutation outcomes. Keep fallback within the same clear spoken request. Require fresh screen reads after navigation and node IDs from the latest read. Respect platform permissions and inaccessible controls; clarify ambiguous targets and report unavailable or failed fallback without claiming success. This policy is model guidance rather than a deterministic execution guarantee.

Treat PWAs packaged as visible Android applications like other discovered applications. Plain home-screen website shortcuts are outside the installed-app catalog; do not enumerate launcher-private shortcut data or infer that an absent native app makes its shortcut unclickable. When accessibility is enabled, use Home, a fresh screen read and the matching visible shortcut node for the requested launch. For a request to open a website with an unambiguous URL, a discovered HTTP/HTTPS browser handler is another suitable route; search without filtering by the website's app name. Do not substitute a website URL for a specifically requested shortcut. Report inaccessible launcher icons honestly.

## Form factors

One Android application module with shared sources and `handheld` (phone/TV) and `wear` flavors. Native layouts must work with touch, D-pad and round screens. Expose `aho.gpt.android.ui.VoiceActivity` and voice-command intents for a separate TV button mapper. Support default-assistant selection through the exported `ACTION_ASSIST` activity on devices exposing the system picker. The system assistant shortcut opens the voice panel and starts listening after setup and microphone permission. Use the installed speech provider; do not register a voice interaction or recognition service that replaces it. No wake word, lock-screen assistant integration or built-in global key mapper. Voice overlays can use an enabled accessibility service or a separately granted overlay permission; voice works without either.

## Logging

Match vibe-navigator's logging behavior with native UI and no runtime dependencies. About & settings places the Logs row under Advanced, immediately after Use external storage, in label, circular 44dp gear, saved enable switch and info-button order. Logging defaults off. The folder dialog shows the actual current folder and compact right-aligned Open, red Delete and OK actions. Delete requires permanent-deletion confirmation, captures its destination, removes only generated `aho-gpt-log-<yyyyMMddHHmmss>[-<collision>].txt` names (including MediaStore collision suffixes), and preserves unrelated files, subfolders and the folder. MediaStore deletion filters by app ownership. Serialize deletion with log writes off the UI thread; close the active file and restart enabled logging with system details first.

Use only `Download/AhoGPT/logs` on the selected phone or supported mounted writable SD storage. Advanced starts with Use external storage, default off, disabled without an available supported card. Exclude USB drives. Android 10+ uses MediaStore Downloads on the selected indexed volume. Android 6–9 phone Downloads requires runtime READ_EXTERNAL_STORAGE and WRITE_EXTERNAL_STORAGE; legacy SD uses persisted read/write SAF access to Download or a valid ancestor. Reuse valid grants, preserve them when switching back to phone storage, and verify writes before selecting SD storage or enabling logging. Permission results and pending log enabling survive activity recreation. Missing or revoked access, removal and write failure disable logging without changing storage selection or redirecting output. Restored storage requires explicitly enabling logging again. Existing files stay in place and survive uninstall. Grants and selection remain device-local and excluded from backups.

Open uses a non-exported transparent host in a separate files task. Launch ACTION_OPEN_DOCUMENT with multiple selection and the selected folder as the initial location on Android 8+. Prepare access off the UI thread and still open the picker if preparation fails. Do not request a folder grant just to browse. Preserve temporary read grants for all selected URIs; offer viewers and sharing for one file, and sharing for several. Deduplicate data and ClipData results. Recreation does not relaunch the picker. Finish and remove only the browser host task after completion or cancellation; reopening replaces it.

Create a timestamped session file on enabling and process restart while enabled. Record system/app details first, then timestamp, level, tag, thread and diagnostic event per entry. Buffer DEBUG entries, flush other levels immediately, and trim above 4 MiB to approximately the last 3 MiB at a complete line. Include lifecycle, catalog counts, speech states and provider error codes, microphone permission results, authentication stages, accessibility and overlay availability, tool-setting revisions, and request progress and elapsed time. HTTP diagnostics use a local sequence, allowlisted operation, method, status, outcome and elapsed time. Record all tool receipts, including pre-dispatch refusals and cached receipts, using only allowlisted function names, states and fixed codes. Never log tokens, client/host/account identity, authorization URLs, HTTP bodies, tool arguments/results, spoken requests, answers or screen contents. Exceptions include only class names and bounded stack locations; omit messages and suppressed exceptions. Uncaught crashes and anomalous Android 11+ previous-process exit metadata may create and flush a log even with routine logging off, subject to the same storage rules. Preserve the prior uncaught-exception handler. Do not retain conversations or use logcat as a second destination.

## Validation

Use PMD with the inherited reference limits, plain JVM unit tests for protocol/session safety, lint for both variants, and debug/release builds with release shrinking. Explicitly distinguish static/build verification from physical-device integration testing. Maintain zero runtime dependencies.

Build with JDK 21, Android SDK 37 and the supplied Gradle 9.8.1 wrapper (AGP 9.4.1, Java 17 sources). Configure the SDK in untracked `local.properties` or `ANDROID_HOME`. Release distribution requires a signing configuration.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat complexityCheck testHandheldDebugUnitTest testWearDebugUnitTest lintHandheldDebug lintWearDebug assembleHandheldDebug assembleWearDebug assembleHandheldRelease assembleWearRelease
```

These checks do not verify live OAuth, spoken requests, provider behavior or physical phone/TV/watch layouts.

An opt-in connected-device regression checks actual voice-task removal after automatic dismissal, explicit close and Android Back. It covers launches from the app, an explicit external component, ACTION_ASSIST and ACTION_VOICE_COMMAND, and verifies that the main app task survives. It temporarily disables STT and restores its saved preference, exercising dismissal through the speech-disabled error path without microphone acquisition, inference or tools. Build and install the handheld debug app and Android-test APK, then run:

```powershell
adb shell am instrument -w -e voice_tasks true aho.gpt.debug.test/aho.gpt.android.tools.IntentLaunchTests
```

These task checks do not verify a live spoken answer, OAuth, TV firmware or watch behavior.

The instrumentation runner also accepts `-e log_storage true` for isolated logging, trimming, privacy, deletion and unavailable-storage checks. On Android 6–9, grant both legacy storage permissions before this test and restore their previous state afterward. The test removes only its own fixtures and preserves app preferences and existing logs. With phone storage selected, logging off and legacy storage access denied, `-e log_permission true` checks that enabling Logs launches Android permission UI and cancellation keeps logging off; it intercepts that launch without granting access. These tests do not cover live SD cards, MediaStore on newer Android versions, or all file-picker UIs.
